Temporal Platform & Standard

Authored a company-wide standard for how every service uses Temporal, then drove the shared workflow platform itself to production-grade security and reliability.

TemporalAWS CDKECS FargateRDSSecrets ManagerKMSIAM
S
Situation

A fast-moving AI startup was adopting Temporal for workflow orchestration across a fleet of microservices — but every team used it differently, and the shared platform wasn't production-grade. There was no common pattern for clients, retries, or payloads, and the deployment carried real security and reliability gaps that blocked dependent services from shipping to production.

T
Task

Two connected mandates: define the standard for how services use Temporal so the fleet stops diverging, and make the shared platform production-ready — the keystone every Temporal-based service depends on.

A
Action

Authored the company-wide Temporal standard: SDK version pinning, a lazy singleton client, namespace-per-service strategy, category-based retry policies (DB / LLM / API / file / cache), a large-payload offload pattern, worker liveness probes, and graceful shutdown.

Then drove the platform to production-readiness single-handed:

  • Migrated the infrastructure to a config-driven CDK stack, removing the legacy implementation.
  • Hardened security: credentials from a secrets manager with rotation, per-service least-privilege IAM roles, customer-managed KMS encryption at rest, TLS in transit, and least-privilege network egress.
  • Built reliability & DR: reliability-standard health checks, per-environment deletion protection, a 35-day backup strategy with a documented restore runbook, and automated recovery from a database failover mode I diagnosed as wedging the cluster.
  • Added CI security gates — secret and dependency scanning, image scan-on-push, and remediation of all critical/high vulnerabilities.
R
Result

A single referenced standard now governs Temporal usage across all Python services, replacing ad-hoc per-service logic. The shared platform meets production security and reliability bars — unblocking the dependent services that were queued behind it — with a documented recovery and restore posture rather than hope.

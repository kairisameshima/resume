Multi-Provider LLM Gateway

A single relay that fronts every LLM provider behind one API — structured outputs, function calling, async job queuing, and streaming — with a cross-cloud migration and 99% test coverage.

PythonFastAPIRedisBedrockGeminiAzure / OpenAI
S
Situation

Multiple services each integrated LLM providers directly — duplicated request/response logic, inconsistent error handling and retries, and mounting provider lock-in risk. Every new model or provider meant touching several codebases.

T
Task

Own a single gateway that unifies all providers behind one stable API, so downstream services integrate once and switch models freely — and make it reliable enough to sit on the critical path.

A
Action

Unified Anthropic (Bedrock), Google Gemini, and Azure/OpenAI behind one API supporting structured outputs, function calling, async job queuing, and Redis-Streams SSE.

  • Led a cross-cloud migration of the relay, consolidating provider access and infrastructure.
  • Drove the service to 99% test coverage (665 tests) with hermetic isolation — every external call patched — eliminating suite flakiness.
  • Diagnosed and fixed a production memory leak and added worker recycling with jitter to stabilize the service under sustained load.
R
Result

One reliable relay for all LLM traffic across the fleet: services integrate once, swap models without code changes, and the gateway stays stable under load — 99% covered and hardened against the failure modes that had bitten it before.
